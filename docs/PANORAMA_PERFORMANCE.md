# 全景性能预算与回归验证

## 问题与修复

- 原始六面图为 4352×4352，总计 32,538,898 字节。RGBA 纹理约 433.5 MiB，另有图片解码和帧缓冲开销；部分设备还可能超过立方体贴图尺寸上限。
- 保留原图，用 `npm run assets:panorama` 生成 JPEG 衍生图。画布宽度小于 768 CSS 像素或 GPU 不支持 2048 贴图时，只下载 1024 六面图；其余使用 2048 六面图，不先下载原图。对应 GPU 纹理预算为 24 / 96 MiB，下载预算为 2 / 6 MB。
- 上传时按 GPU 尺寸上限缩小超大输入，避免以后换图再次上传无界纹理。六面加载完成只上传一次，丢失上下文后复用已加载图片恢复，退出时释放纹理、监听器和动画。
- 拖动、滚轮和尺寸变化合并到一帧一次重绘；静止不重绘。自动带看的 RAF 直接渲染，不再额外排一条渲染循环。
- 使用 ResizeObserver 缓存 CSS 尺寸，输入、渲染和热点投影不读取布局。热点通过 transform 移动，不改 left/top；移除热点背景模糊，避免画面变化时重复采样背景。
- 关闭全屏纹理不需要的多重采样、深度和模板缓冲。DPR 上限 1.5，帧缓冲约束在 200 万像素附近，避免高分屏放大填充成本。

取舍：移动端优先加载和流畅度，放大后的细节不等同于原始 4352 贴图；没有后台继续下载原图，也没有无界纹理缓存。

## 本机对比

在 390×844、deviceScaleFactor=3 的 Chromium 无头浏览器（软件 WebGL）中，冷页面实测：

- 全景下载：32,538,898 → 1,563,501 字节（减少约 95%）。
- 加载就绪：约 966 → 130 ms（单轮观测，不作为跨设备性能承诺）。
- 同帧突发 120 次拖动：121 → 1 次重绘，1092 → 0 次画布布局读取。
- 绘图缓冲：780×1311 → 585×983。

不以本机软件 WebGL 的 FPS 代替真机测试；仍需在目标手机上确认放大细节和持续拖动体验。

## 验证

```bash
node --test tests/panorama.test.mjs tests/panorama-guidance.test.mjs tests/foundation.test.mjs
node scripts/verify-panorama-performance.mjs
node scripts/verify-panorama-guidance.mjs
```

浏览器脚本支持通过 `VIRTOUR_PLAYWRIGHT_PATH` 指向 Playwright 的绝对入口文件。性能脚本分别验证手机和桌面只下载对应六张衍生图、实际纹理尺寸、下载预算、同帧输入合并、零布局读取、静止零重绘及退出资源清理，不依赖外部模型和真实密钥。
